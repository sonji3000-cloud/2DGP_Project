# 피코슈타인 시점 전환 구현 참고

Python과 Pico2d에서 **같은 2D 월드를 탑뷰와 레이캐스팅 1인칭으로 그릴 수 있다.** 탑뷰에서는 타일과 객체의 위치를 화면에 그대로 옮긴다. 1인칭에서는 플레이어가 바라보는 방향으로 여러 광선을 보내 가장 가까운 벽을 찾고, 거리에 따라 높이가 다른 세로 띠로 그린다. 이 방식은 울펜슈타인 3D처럼 높이가 일정한 벽과 평평한 바닥으로 구성된 맵에 적합하다. [울펜슈타인 3D 원본 렌더러](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/WL_DRAW.C)

| 방식 | 구현할 때 달라지는 점 |
| --- | --- |
| **시점 전환** | 한 프레임에 탑뷰 또는 1인칭 하나를 그린다. 시제품에서는 `Tab`을 전환 키로 사용해 같은 위치의 벽과 문을 두 시점에서 비교할 수 있다. |
| **1인칭과 탑뷰 미니맵** | 1인칭 화면 위에 작은 탑뷰를 추가한다. 플레이어와 주변 타일만 표시하면 기존 탑뷰 좌표 변환을 재사용할 수 있다. |
| **분할 화면** | 한 프레임에 두 시점을 별도 영역에 그린다. 영역별 좌표 변환과 잘라내기가 필요하고, 두 화면의 그리기 비용을 함께 측정해야 한다. |

시제품은 **시점 전환**을 기준으로 한다. 미니맵이 필요해지면 탑뷰 렌더러에 화면 위치와 축척을 넘겨 같은 월드의 일부를 그린다.

## 공유하는 월드와 좌표

| 데이터 | 공유 규칙 |
| --- | --- |
| 격자 맵 | `tiles[tile_y][tile_x]`에 바닥, 벽, 문을 저장한다. 월드에서 타일 한 칸의 폭과 높이는 각각 `1.0`이다. |
| 플레이어 | 실수 좌표 `(x, y)`와 바라보는 각도 `angle`, 체력, 무기, 탄약, 열쇠를 한 곳에서 관리한다. |
| 적과 아이템 | 일반병·군견·베테랑 병사, 열쇠와 보급품의 위치 및 상태를 공유한다. 탑뷰에서는 해당 좌표에 그리고, 1인칭에서는 카메라 기준으로 투영한다. |
| 문 | `locked`는 열 수 있는지를, `is_open`은 통과할 수 있는지를 나타낸다. 잠금이 풀려도 닫혀 있으면 벽처럼 처리한다. |
| 카메라 | 탑뷰의 화면 원점과 축척, 1인칭의 시야각과 광선 개수를 렌더러에서 관리한다. |

- 월드의 오른쪽을 `+x`, 위쪽을 `+y`로 두고, 각도 `0`은 오른쪽을 향한다. 각도는 라디안으로 계산한다. 위쪽부터 작성한 텍스트 맵은 읽을 때 행 순서를 뒤집어 `tile_y = 0`이 맨 아래가 되도록 맞춘다.
- 타일 좌표는 `floor(x)`, `floor(y)`로 계산한다. 배열에 접근하기 전에 범위를 검사하고, 맵 바깥은 막힌 공간으로 취급한다.
- `blocks_tile(tx, ty)`가 벽과 닫힌 문의 차단 여부를 반환하도록 한다. 플레이어와 적의 이동은 몸체 반경을 포함해 검사하고, 총알과 시야는 이동 구간이나 광선을 따라 막히는 지점을 검사한다. 양쪽 화면은 같은 문 상태를 읽는다.

## 입력과 프레임 처리

탑뷰에서 `WASD`는 화면 상하좌우 이동으로 해석한다. 1인칭에서는 `W/S`를 전진·후진, `A/D`를 바라보는 방향 기준 좌우 이동으로 해석하는 안을 시제품에서 확인한다. 양쪽에서 `Q`는 `angle`을 늘려 반시계 방향으로, `E`는 줄여 시계 방향으로 회전한다. 스페이스바는 해당 각도로 발사한다. 대각선 이동 입력을 정규화한 뒤 이동 속도와 경과 시간 `dt`를 곱한다.

입력 처리와 월드 갱신은 시점 전환 여부와 관계없이 프레임마다 한 번 수행한다. `Tab`은 눌림 상태가 처음 바뀔 때 한 번만 처리한다. 키를 누른 채 시점을 바꾸면 이동 기준이 바뀌므로, 이동 중 전환도 시제품에서 확인한다.

```python
# 구조 예시. 함수와 상태는 게임 코드에서 정의한다.
handle_input(input_state)
if input_state.just_pressed("tab"):
    active_view = toggle_view(active_view)

update_world(world, input_state, active_view, dt)

clear_canvas()
renderers[active_view].draw(world)
draw_hud(world.player)
update_canvas()
```

`update_world`에서는 먼저 회전을 적용한 뒤 갱신된 각도로 1인칭 이동과 발사 방향을 계산한다. 무기 발사 간격, 총알 충돌, 적 AI, 열쇠 획득 및 탈출 판정도 같은 함수에서 갱신한다. 렌더러는 월드 상태를 읽어 화면을 그린다. 시점을 바꿔도 진행 중인 총알이나 발사 대기 시간은 이어진다.

## 탑뷰 그리기

1. 월드 좌표에 픽셀 축척을 곱하고 카메라 원점을 적용해 화면 좌표를 계산한다.
2. 벽, 닫힌 문, 플레이어, 적, 아이템을 그린다. 플레이어 위치에서 `angle` 방향으로 짧은 조준선을 그린다.
3. 개발 중에는 1인칭 시야 범위와 중앙 광선의 충돌 타일을 겹쳐 표시한다. 어느 문에서 광선이 멈추는지, 열린 문을 통과하는지 확인하기 쉽다.

## 1인칭 레이캐스팅

1. **카메라 방향을 계산한다.** `forward = (cos(angle), sin(angle))`, `right = (sin(angle), -cos(angle))`로 둔다. 화면을 `N`개의 세로 띠로 나누고, `i`번째 띠에 대해 `u = 2 * (i + 0.5) / N - 1`을 계산한다. 광선 방향은 `forward + right * u * tan(fov_x / 2)`다. `fov_x`는 가로 시야각이다.
2. **격자를 따라 첫 벽을 찾는다.** DDA는 광선이 다음 가로 또는 세로 타일 경계를 만나는 지점 중 가까운 쪽으로 이동한다. 막힌 타일이나 맵 경계에서 멈춘다. 광선의 x 또는 y 성분이 0이면 해당 축의 다음 교차 거리를 무한대로 둔다.
3. **화면에 투영한다.** 이 광선 방향을 정규화하지 않고 DDA에 사용하면 `hit = player_pos + t * ray_dir`의 `t`가 카메라 앞 방향 깊이가 된다. 화면 폭이 `W`픽셀이면 투영 거리 `f = W / (2 * tan(fov_x / 2))`를 구한다. 벽 높이가 `1.0`일 때 화면상의 벽 높이는 `f / max(t, near)`다. `near`는 0에 가까운 거리에서 나눗셈과 그리기 크기가 불안정해지는 것을 막는 작은 양수다. 화면 중앙의 수평선을 기준으로 벽 띠를 배치한다.
4. **세로 띠를 그린다.** 설치된 Pico2d 1.5.1에서 `draw_rectangle(..., filled=True)`와 `Image.clip_draw(left, bottom, width, height, x, y, w, h)`를 확인했다. 처음에는 사각형으로 거리에 따른 높이를 확인한다. 텍스처를 붙일 때는 충돌 지점의 타일 내 위치로 텍스처의 세로 조각을 골라, `clip_draw`로 화면 띠 너비와 벽 높이에 맞춰 그린다. [Pico2d 배포 페이지](https://pypi.org/project/pico2d/)
5. **적과 아이템을 가린다.** 각 띠의 벽 깊이 `t`를 저장한다. 객체와 플레이어의 위치 차이를 `forward`, `right`에 각각 내적해 객체 깊이와 좌우 오프셋을 구한다. 깊이가 `near`보다 큰 객체는 화면 가로 위치 `W / 2 + f * 좌우_오프셋 / 깊이`에 배치하고, 크기를 깊이에 반비례하게 그린다. 먼 객체부터 그리되, 스프라이트가 덮는 각 띠에서 객체 깊이가 벽보다 가까울 때만 그 조각을 그린다. 조각별로 검사하면 문틀에 몸 일부만 가려진 적도 표현할 수 있다.

1인칭의 화면 깊이는 그리기에 사용한다. 권총과 산탄총의 명중은 공통 월드 좌표에서 계산한다. 한 프레임에 총알이 이동한 선분에서 벽·문과 적 중 먼저 닿은 대상을 선택하면, 시점이나 광선 개수에 따라 명중 결과가 달라지지 않는다.

## 구현 순서와 확인 항목

| 순서 | 만들 것 | 확인할 것 |
| --- | --- | --- |
| 1 | 방 두 개, 문 하나, 플레이어를 탑뷰로 표시 | 이동과 회전, 벽 충돌, 열쇠 획득 후 문 개방이 작동한다. |
| 2 | 같은 방의 벽을 색 띠로 그리는 1인칭과 `Tab` 전환 | 이동하거나 회전한 상태에서 전환해도 위치와 각도가 이어진다. 평평한 벽이 화면 가장자리에서 불필요하게 휘지 않는다. |
| 3 | 닫힌 문과 적 스프라이트의 가림 처리 | 닫힌 문 뒤의 적이 가려지고, 문을 열면 통로와 적이 보인다. 문틀 뒤에서 적의 일부만 보인다. |
| 4 | 권총, 산탄총, 적과 열쇠를 공통 월드에 연결 | 같은 위치와 조준 방향에서 발사 결과가 같다. 교전 중 전환해도 체력, 탄약, 적 상태, 문 상태와 열쇠가 이어진다. |
| 5 | 적과 총알을 늘리고 텍스처를 추가 | 월드 갱신과 그리기에 걸린 시간을 따로 잰다. 예를 들어 광선 120개에서 시작해 띠 너비와 프레임 시간을 비교한다. 광선 개수는 실제 측정 후 정한다. |

맵 한 곳에서 두 시점과 문 가림을 확인한 뒤 본 맵에 적용하면, 열쇠 백트래킹과 탈출 로직도 같은 코드로 검증할 수 있다.
